## 先确定“完全按照论文”的含义

论文 §3 本身包括 R&D-Factor、R&D-Model、联合 R&D-Agent(Q) 三种配置。当前 `fin_factor` 对应第一种，并非错误入口；只有复现完整联合系统才应使用 `fin_quant`。论文附录 C.2 的初始库就是 Alpha20，所以当前 20 个基础特征应保留，不能按 UI 的 Alpha158 Plus 文案改成 158 个。

建议建立独立 `paper-v2` 实验配置，以 CSI300 主实验为默认目标。若保留 CSI500、当前切分、DeepSeek 或本地 IC-first 规则，则应命名为论文方法的本地适配，而不是原表格复现。

当前代码基线是 2026 年版本且含多项本地修改，论文 v2 为 2025 年版本。论文没有在已核对部分给出能唯一锁定整套实验的 Git commit、所有模型快照和数据版本。可实现有明确记录的协议对齐，不能承诺仅靠改几个环境变量就数值完全相同。

### 新核实的 Bandit 缺陷

`scenarios/qlib/proposal/bandit.py` 读取的收益键是 `1day.excess_return_with_cost.annualized_return `，尾部多一个空格。用 Loop_8 真实工件调用当前提取函数：

```text
实际保存 ARR：0.0864520568747058
Bandit 读出的 ARR：0.0
Bandit 末项指标：0.0
```

完整联合运行前必须修复，否则收益没有按设计进入动作选择。

还应核对八维状态的定义：当前名为 `sharpe` 的值实际为 ARR/绝对回撤，属于 Calmar 形式；Qlib 回撤为负数，与调度器转换后的好坏方向需统一。贝叶斯更新中的 precision 与 mean 应以固定数值样例对照预定数学实现，不能只看类名叫 LinearThompson。

论文附录 F.1 声称限制同一方向连续探索长度，当前控制器未见此计数和约束。严格对齐需要补该行为，但阈值没有在已核对原文中明确给出，应列为作者配置待确认，不能自定后宣称完全一致。

动作由调度器确定后，也应验证最终生成的 `hypothesis.action` 与实际 dispatch 一致，不能只打印一次选择就视作正确执行。

## 2. 修改实验入口与时长

代码和配置通过验收后，启动形态为：

```bash
rdagent fin_quant --all-duration 12h
```

这只是计划中的最终命令。当前缺陷尚存，不应据此直接启动昂贵长跑。

## 4. 修正数据导出范围与来源

当前 `factor_data_template/generate.py` 将全量因子源数据硬截为 `2008-12-29` 之后。即使 `.env` 改成 2008 年初训练，生成因子在前面近一年仍没有原始数据。

应根据训练起点和最长 lookback 生成足够预热数据，而非另写一个不相干的固定日期。源数据股票池也要与预注册的排名/中性化口径一致；当前 csi800 导出不应未经说明保留为 CSI300 主实验的排名总体。数据导出目录和回测缓存使用新的实验命名空间，保留旧数据用于对照。

当前六个字段是开收高低、成交量与复权因子，没有论文附录列出的 ROE、估值、增长等 Wind 基本面字段。若复现使用这些输入的实验，需要补真实的点时数据与披露时序，并更新数据说明；不能拿 `$factor` 复权字段冒充基本面。公开说明不足以完全确定每个表格使用的最终字段和数据快照，这部分需作者工件或清楚声明缺失。

当前数据包是后续更新的数据快照，即使只切历史日期也不必然等于原实验版本；成分历史、复权和缺失值修订都应记录。完全数值复现需要锁定数据版本，不是仅把 test_end 改早。

## 6. 取消本地额外研究政策，保留必要的执行修复

`feedback.py` 的 IC-first 硬规则与原提示词的收益导向不同。严格代码协议复现应将因子与模型分支的 SOTA 判断统一回选定版本的分析流程，并记录主要目标。仅把 `QLIB_FACTOR_ACCEPT_MIN_IC_GAIN` 设为 0 仍不够，因为代码继续要求 IC/Rank IC 不下降。

因子提案器中“全程禁止机器学习因子”的本地限制也改变了搜索空间。需要对照目标版本恢复相同研究范围，并用正确的执行预算支撑，而不是重新引入无限内部训练。联合提案器和独立提案器必须采用同一策略。

暂不把 FactorMiner 记忆禁区、相关阈值 0.5、额外家族预算或其他新搜索算法混入论文对照实验。它们可以作为后续改进组，但不是论文复现组。

论文 §2.4 本来就描述 0.99 的时间平均最大正相关去重。把它改成更严格绝对相关虽可能改善研究，却也属于算法变化；需要在单独改进组说明。修复 `tasks/sub_tasks` 字段错误则属于实现修复，两者不能混为一谈。

## 7. 预处理、标签和交易描述存在需要确认的口径差异

已在实际 `local_qlib:latest` 容器内只读检查：当前 RobustZScoreNorm 在训练期汇总拟合中位数和 MAD，再用于后续数据；Fillna 默认填 0。论文附录 B 描述的是逐日横截面 robust 处理以及前向填充加横截面均值。

当前标签为 `Ref($close,-2)/Ref($close,-1)-1`，论文附录 B 的公式写作 t 至 t+1 收益。交易章节同时出现次日开盘决策、按收盘价成交及保留高排名持仓的说明，正文又使用 long-short 称谓，而代码是 TopkDropoutStrategy。

所以不能为了“完全一致”直接把标签前移、把成交价改成 open，或者自行增加空头腿。必须选择并明确：

- 以论文对应发布代码作为执行真相，保留它的标签和 Qlib 时间对齐，并声明文字差异；或
- 按论文数学口径重建处理器和交易时序，并作为另一个协议记录。

最好的消歧依据是作者的固定提交、配置与一组可复算结果。在缺失时，把这些列为待确认项，比猜一个设置后宣称精确复现可靠。

现有 topk=50、n_drop=5、收盘成交、买费 0.0005、卖费 0.0015、最低 5 元和 0.095 阈值已与主要公开代码/交易参数对应，不应无理由改动。

## 8. 时间、缓存、统计与验收

Co-STEER 内循环 10 次应保持。当前因子 Python 执行 timeout 为 900 秒，与论文实现单元预算 600 秒不同；不能只改 subprocess timeout 就宣称整个实现单元总预算一致。需要在任务层控制各次模型调用、执行和重试的累计时长。验证单元 3600 秒在当前有效 QlibDockerConf 中已生效。

应使用新 run、配置和缓存命名空间开始论文组；不继承此前 CSI500/不同切分下的 SOTA 或知识库。论文启用了持久缓存，正确做法是修缓存身份和信息恢复，而非为回避缺陷一律关缓存。跨进程知识库按需求配置并与该实验隔离；原系统单次进程内已有知识累积，不需要误判成完全禁用。

论文明确对基线模型做五个随机种子并报告 ARR 中位数，单次结果不能直接与其统计摘要横比。Agent 搜索本身如何重复也应预注册并保留独立运行结果，不能选择最好一晚代表整体表现。

长跑前至少验收：

1. 因子分支和模型分支各完成一个不付费的接口回放；实际输入包含所需信息。
2. 调度器正确读取收益、指标方向正确，选择和 dispatch 一致。
3. 实现改变、配置改变、数据改变时缓存身份正确；命中后日志与指标不脱节。
4. 任务—工作区对齐，SOTA 归属与编号一致。
5. baseline 与候选使用相同预处理和统计口径；未来数据截断检查实际执行。
6. 一个小规模真实烟雾实验成功后再使用完整时长；真实实验会产生费用，此清单没有启动它。
